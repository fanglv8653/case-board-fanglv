# V084-N0 验收标准

## 通用

1. 报告逐项引用真实源码、迁移、workflow 或发布脚本位置；
2. 明确区分已存在能力、缺口、设计决定和待主控裁决事项；
3. 不读取正式数据库、凭据、NAS 或正式飞书 Base；
4. 不修改产品源码、迁移、版本、依赖、公开清单和远端状态；
5. 给出稳定错误码、失败原子性和确定性测试建议；
6. 给出后续任务的非重叠文件范围和依赖关系。

## 更新/发布专项

- 解释 `downloadAndInstall()` 后代码不可达的真实生命周期；
- 给出跨进程、跨版本、一次消费且失败不误报的状态设计；
- 把两个公开清单纳入同一最终发布事务并覆盖恢复场景；
- workflow 与远端实际资产名均以 ASCII 为事实源。

## 待办专项

- 解决现有 `case_todos.case_id NOT NULL` 与未关联事项的冲突；
- 明确是否演进旧表或引入新表，并给出兼容迁移依据；
- 复制到案件进展必须同事务防重、按事项时间可排序、后续解耦；
- 覆盖新增、修改、完成、软删除、关联/解除关联及历史案件内待办兼容。

## 飞书专项

- 只使用同步层，不允许外部直写 SQLite；
- 稳定 ID、来源、版本、基线哈希、冲突状态足以防环；
- 第一阶段不传播物理删除；
- 所有远端写入均须用户明确操作或已冻结的安全自动同步策略；
- 离线、权限不足、远端结构漂移和并发修改均失败关闭。
