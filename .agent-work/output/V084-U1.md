# V084-U1：可靠更新生命周期实现

状态：`submitted_for_review`

## 交付结论

已将 Windows 应用内更新从前端直接安装模型改为 Rust 协调模型：Rust 仅使用锁定 updater 插件的 `check()` 与 `download()`（下载完成即完成 minisign 验证），不调用插件 `install()` / `download_and_install()`；独立 helper 必须等待 sidecar/SQLite 收尾耐久屏障与旧 PID 同时满足后才启动 NSIS。安装器退出码、目标版本和当前用户专用 ACL 回执全部通过后，新版本才能一次性 claim 并显示成功。

本任务未修改版本号、公开清单、发布脚本、Release、tag 或远端状态。

## 主要实现

- 新增 `src-tauri/src/update_lifecycle.rs`：
  - 常驻专用 shutdown coordinator OS 线程；线程自建 current-thread Tokio runtime，顺序执行 `lifecycle::shutdown()`、`pool.close().await`、耐久状态转换。
  - `start_app_update` 负责严格版本核对、签名下载、进度事件、安装包与 helper 安全落盘、helper ready、停机请求及安全退出。
  - `claim_app_update_success` 只接受命令行非秘密 `attempt_id` 对应的合法、未过期、安装成功且目标版本一致的回执；进程级互斥及原子 rename 保证至多消费一次。
  - Windows 状态目录和文件关闭 ACL 继承，仅保留当前用户 SID 的 Full Control ACE；每次读写/claim 前复核 owner、protected DACL、唯一 ACE、权限及重解析点。
  - 签名失败独立映射 `UPD_SIGNATURE_INVALID`；下载、屏障、安装器、目标版本、ACL、持久化和消费均使用稳定错误码。
- 新增 `src-tauri/src/bin/caseboard-updater-helper.rs`，并在 Cargo 注册独立 helper binary。helper argv 仅含 attempt id、受限状态路径、包路径、旧 PID 和目标 exe 路径，不传 token、密钥、回执正文、环境秘密或 SQLite 数据。
- `src-tauri/src/main.rs` 新增无 WebView 的 `--caseboard-print-version` 入口，供 helper 安装后核对目标版本。
- `src-tauri/src/lib.rs` 注册 coordinator 和两个 Tauri 命令；原有窗口销毁收尾保留为幂等兜底。
- `src/lib/updater.ts` 改为 invoke/listen 薄封装，不再导入前端 updater/process 插件，不写浏览器缓存，不推断安装成功。
- `src/components/UpdateAvailableDialog.tsx` 使用稳定错误码；屏障超时或 ack 断开进入不可重试的安全收尾提示，避免半关闭状态重复更新。
- `src/lib/updater.contract.test.mjs` 冻结“前端不得安装、Rust 不得调用插件 install、成功仅由回执 claim”约束。
