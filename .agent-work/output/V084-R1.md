# V084-R1：Windows 原子发布链

状态：`submitted_for_review`

## 交付结论

已把 U1 独立 helper 纳入 Windows NSIS 打包，并将发布链收紧为“冻结 tag 构建 → 精确 ASCII 双资产 staging → draft Release 上传/摘要回读 → 正式 Release 回读 → `version.json` 与 `latest.json` 同一提交快进推送 → raw 双清单回读”。本任务没有修改当前 0.8.3 公开清单、版本号、tag、GitHub Release 或其他远端状态。

## 主要变更

- `src-tauri/tauri.conf.json`
  - 注册 `binaries/caseboard-updater-helper` 为 external binary；Tauri 按 Windows target triple 嵌入并安装为主程序同目录 helper。
- `.github/workflows/build-windows.yml`
  - checkout 指定 release tag，禁用凭据持久化，并在安装依赖前核对严格 tag 语法、tag ref 与 HEAD。
  - release 模式预先构建 helper，复制为 Tauri 所需 `caseboard-updater-helper-x86_64-pc-windows-msvc.exe`。
  - 将 Tauri 原始中文 NSIS 名复制到空 staging，唯一事实名固定为 `FanglvCaseBoard_<version>_x64-setup.exe` 及同名 `.sig`。
  - minisign、Authenticode 状态记录、清单 draft 和上传 artifact 全部只读取 staging 事实。
- `scripts/release-gate.mjs`
  - source gate 验证 helper Cargo 注册、源码与 externalBin 配置。
  - release gate 仅允许稳定三段版本与精确、区分大小写、全 ASCII、恰好两个文件的资产目录。
- `scripts/publish-release-resumable.ps1`
  - 本地及远端资产集合必须精确等于双资产，名称、size、SHA-256 任一漂移均失败关闭。
  - 新 Release 只创建 draft；资产逐项上传且回读完整后才 `--draft=false`，再回读正式状态与 target commit。
  - 正式 Release 事实生成 `version.json`，并与已验证 `latest.json` 做同版、URL、签名和说明交叉校验。
  - 暂存区必须为空；提交文件集合必须恰好是两份清单；提交信息为 `chore: publish <version> release manifests`；仅普通快进推送，绝不强推。
  - push 超时先查询远端是否已收敛；成功后从 raw GitHub 回读两份清单并逐字核对。
- `scripts/release-resume-core.psm1` / `scripts/test-release-resume.ps1`
  - 新增精确资产对和双清单计划函数；覆盖中文名、大小写变体、错误版本、多余资产、版本/Release URL 漂移等失败分支。
- `scripts/release-pipeline.contract.test.mjs`
  - 冻结 helper 打包、tag 构建、ASCII staging、draft 正式化、双清单单提交及无强推契约。
