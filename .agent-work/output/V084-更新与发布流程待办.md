# v0.8.4 更新与发布流程及产品范围

状态：`confirmed_for_v0.8.4`

## 更新与发布链

1. Windows 更新生命周期必须区分下载、旧进程退出、安装器结果和新版本首次启动。
2. 更新成功只允许在新版本启动后依据旧版本、目标版本及一次性状态核验显示。
3. 安装失败、取消、签名失败和旧进程无法退出不得写入成功状态。
4. 正常退出仍须关闭数据库连接并收敛 sidecar，不得恢复强杀应用逻辑。
5. 发布顺序为冻结提交、tag 构建、验签与覆盖验收、Release 资产、最后原子更新两个公开清单。
6. `version.json` 与 `latest.json` 必须在同一发布提交中更新，且该提交不得夹带其他文件。
7. Windows 资产名固定为 `FanglvCaseBoard_<version>_x64-setup.exe` 及同名 `.sig`。

## 待办事项

1. 案件看板板块名称为“待办事项”；飞书交换表名称仍为“收件箱”。
2. 待办支持录入、查看、修改，允许暂未关联案件。
3. Hermes/NAS 不得直接修改案件看板 SQLite，只经飞书接口和案件看板同步层交换。
4. 使用稳定事项 ID、来源、同步版本和冲突状态防止重复写入及循环同步。
5. 第一阶段不自动传播物理删除，删除与冲突进入人工确认。
6. “一键复制到案件进展”仅由人工触发；未关联事项先选案件。
7. 复制内容至少含标题、内容、事项时间、来源和源事项 ID，按事项时间插入时间线并防重。
8. 复制后待办与案件进展相互独立，后续修改或删除待办不得静默改写既有进展。

## 发布前硬门禁

- 真实旧版应用内更新；新版本首次启动一次性提示；失败分支无假成功；
- 退出后相关进程归零，数据库 `quick_check=ok`，无 WAL/SHM/journal；
- 公开清单、tag、Release target、资产 digest、URL 和签名远端回读一致；
- 待办本地/远端双向、冲突、删除、重复、循环和复制防重均有确定性测试；
- 正式发布必须在用户审阅 RC 结果后另行执行。
