# V084-T1 交付报告

## 结论

已按 R2 契约完成 0.8.4 本地“待办事项”数据模型、顶层板块、软删除/恢复，以及“复制到案件进展”的单事务幂等语义。未改版本号、公开更新清单、依赖或远端状态。

## 实现范围

### 数据库与兼容迁移

- 新增 `0064_global_todos.sql`，原位演进 `case_todos`，没有创建并行待办表。
- `case_id` 改为可空，案件删除时 `ON DELETE SET NULL`。
- 新增内容、类型、优先级、标签、下一步、状态、事项时间、提醒时间、来源和软删除审计字段。
- 保留 `done/done_at/due_date` 作为 0.8.3 兼容投影；旧 `due_date` 按上海零点迁移为 `due_at`。
- 重建索引、来源不可变触发器和设备同步脏实体触发器；设备同步注册表纳入全部新字段。

### Rust 业务层与 IPC

- 新增全局筛选、案件关联/解绑、软删除、恢复和稳定错误码。
- 本地创建来源固定为 `caseboard`；类型、优先级、状态、日期和带时区时间均失败关闭校验。
- 首页仅统计未删除、可行动类型 `todo/reminder` 且处于 `inbox/in_progress/waiting` 的事项。
- `due_at` 到兼容 `due_date` 的投影使用上海日历日，避免 UTC 换算导致前一天。
- “复制到案件进展”在一个 SQLite 事务中完成：
  - 已绑定事项只能复制到绑定案件；未绑定事项必须显式给出目标案件。
  - 时间顺序为 `due_at -> remind_at -> due_date 上海零点 -> created_at`。
  - 使用 `external_source='case_todo' + external_record_id=todo.id` 现有唯一索引和 `ON CONFLICT DO NOTHING` 防重复。
  - 重复复制返回既有记录；跨案件冲突和既有软删除进展返回稳定结果/错误码。

### 前端

- 顶部模块新增“待办事项”。
- 支持新建未关联/已关联事项、类型、优先级、事项时间、全局搜索、案件和状态筛选。
- 支持完成/重新打开、关联/解绑案件、移入回收站、恢复、复制到案件进展。
- 案件详情旧待办卡保持兼容；首页可显示“未关联案件”而不会误导航。
