# 05 验收标准

## 通用硬门禁

1. 目标、输入、输出和允许文件范围完全一致；
2. 无正式数据库、NAS、飞书正式 Base、凭据或业务正文读写；
3. 无 `git reset`、覆盖他人修改、无关重构或依赖漂移；
4. 生产实现必须有确定性回归测试；失败路径不得产生部分写入；
5. 稳定错误码用于程序分类，不依赖中文错误文本；
6. Worker 提交实际命令、退出码、测试计数、Git diff 和遗留风险；
7. 主控复验通过后才能 accepted。

## N0 专项门禁

- 未修复代码下，迁移谱系和循环外键夹具能稳定证明现有缺陷；
- 501+ 实体分包边界有确定性夹具；
- checksum 白名单只接受有来源的真实旧值，未知值保持待核验；
- schema sentinel、错误码、可重试/自动暂停语义形成书面契约；
- N0 不改变生产行为。

## 驳回条件

- 缺少核心夹具、只写报告没有可执行证据；
- 测试“通过”是因为绕过外键、删除失败数据或放宽断言；
- 越权写入其他线程/正式数据/公共迁移编号；
- 未报告失败、跳过项或环境限制；
- 把 `submitted_for_review` 当成验收通过。
